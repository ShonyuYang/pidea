## 前言

家裡有小孩的人大概都有同樣的困擾：想讓孩子接觸科技和知識，但平板電腦一拿起來就是無盡的 YouTube 和遊戲。CueHub 的作者 Satish Chilakala 決定從硬體層面解決這個問題——不是寫一個「家長控制 App」，而是從零打造一整套硬體生態系統，讓孩子透過語音和實體按鈕與 AI 互動，完全跳過「滑手機」這個動作。

## 專案概述

CueHub 是一個由兩個核心元件組成的生態系統：

**中央中樞：** Raspberry Pi CM4 連接 16 吋便攜觸控螢幕，作為家中的「大腦」和環境顯示器。它不是傳統的平板介面——沒有 App Store、沒有鍵盤輸入，而是一個純粹的資訊視覺化平台。

**穿戴裝置：** 作者自製的 ESP32-S3 穿戴裝置（之前的專案 Cue Watch 和 Cue Button 的延伸），孩子按下實體按鈕就能發出語音指令，CM4 中樞接收後即時渲染視覺化結果。

整套系統的設計哲學是「零摩擦語音管線」（zero-friction voice pipeline）：按按鈕 → 說話 → 看結果。沒有登入、沒有選單、沒有通知轟炸。

## 技術亮點

### 語音驅動的 Skill 系統

CueHub 採用類似 Alexa 的 skill 架構，但所有視覺化都在本地的 16 吋螢幕上渲染。作者已經原型了幾個令人印象深刻的 skill：

- **迷你航管系統：** 串接 OpenSky Network API 和 MapLibre 地圖，孩子可以語音說「Show me all A380s」或「Zoom into SFO」，即時顯示全球航班動態
- **太陽系探索器：** 真實比例的行星大小比較和加速軌道運動視覺化
- **互動元素週期表：** 語音說「Show me noble gases」就能高亮對應類別，還會渲染原子結構和波耳模型
- **語音數學練習：** AMC 等級的數學題搭配螢幕上的協作草稿板

### 硬體與軟體的垂直整合

作者刻意不用平板 App 的原因很有意思：

1. **對抗分心陷阱：** 平板是「目的地裝置」，會把孩子拉進 App 切換和通知的漩渦。CueHub 是「環境裝置」，獎勵好奇心但不索取注意力
2. **硬體一致性：** 要讓中樞和穿戴裝置原生同步，必須掌控整個硬體堆疊，這在通用平板框架裡做不到

### AI 加速的開發流程

作者提到整個軟體堆疊——語音管線、動態 API 整合、D3.js 視覺化、硬體同步——花不到一週就完成了。他使用 GPT 和 Claude 作為「架構和執行的思考夥伴」，從草圖到客廳裡的實體硬體幾乎是零距離。

## 心得與延伸

CueHub 最讓人眼前一亮的不是某個單一技術，而是它的**設計哲學**。在人人都在討論如何用軟體限制螢幕時間的時代，作者選擇從硬體形態上重新定義「孩子與科技的互動方式」。

這個專案特別值得關注的幾個方向：

- **CM4 的選擇很聰明：** 比起 Pi 5，CM4 更適合嵌入式部署，可以設計專用的載板來整合音訊、觸控、無線通訊
- **ESP32-S3 穿戴裝置的潛力：** S3 內建 USB OTG 和向量指令集，未來可以加入邊緣端的關鍵詞偵測，不用每次都把音訊傳回 CM4
- **Skill 系統的可擴展性：** 目前的 skill 都偏教育向，但架構本身可以延伸到家庭自動化、健康追蹤、行程管理等場景
- **開源潛力：** 如果作者釋出硬體設計和軟體框架，這可以成為一個很棒的親子 DIY 專案

唯一的疑問是長期維護——當孩子長大、需求改變時，這套系統能否優雅地演化？但這也許正是自製硬體的魅力：你永遠可以改。
