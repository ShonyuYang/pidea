## 前言

如果你是 TCG（Trading Card Game）玩家，應該都有過這樣的經驗：從鞋盒裡翻出一疊不知道什麼時候買的卡片，然後花整個下午一張一張查價格、分類整理。

一千張？那就是一千次重複動作。

這位 Maker 決定讓機器來做這件事。用 Raspberry Pi 3B+ 當大腦負責影像辨識，Arduino Nano 控制機械結構，打造了一台能自動掃描、辨識、分類 Magic: The Gathering 卡片的機器。目前是可運作的原型，而且還在持續進化中。

## 專案概述

### 系統架構

這台卡片分類機採用經典的「雙控制器」架構：

| 元件 | 角色 | 負責工作 |
|------|------|----------|
| **Raspberry Pi 3B+** | 大腦 | 影像擷取、卡片辨識、決策邏輯 |
| **Arduino Nano** | 手腳 | 控制馬達、機械分類機構 |

### 運作流程

```
放入卡片堆 → 進紙機構取一張 → 攝影機拍照 → 影像辨識 → 查詢資料庫 → 分類投放
     ↑                                                              |
     └──────────────────── 取下一張 ←────────────────────────────────┘
```

1. **進紙**：機械結構從卡片堆中取出一張卡片
2. **掃描**：攝影機對卡片拍照
3. **辨識**：Pi 透過影像處理辨識卡片名稱和版本
4. **分類**：根據辨識結果，Arduino 控制機構將卡片投入對應的分類槽

### 辨識方式

MTG 卡片辨識通常有幾種主流做法：

- **Scryfall API 比對**：拍照後用 OCR 讀取卡片名稱，再透過 Scryfall API 查詢完整資訊（價格、稀有度、系列等）
- **影像雜湊比對**：用 OpenCV 計算卡片影像的 perceptual hash，與資料庫中的雜湊值比對
- **Google Cloud Vision API**：上傳影像到雲端做辨識

以這個專案的 Pi 3B+ 算力來看，本地端 OCR + Scryfall API 是最實際的組合。

## 技術亮點

### 雙控制器分工

這是嵌入式專案中非常常見且實用的架構模式：

- **Pi 負責「思考」**：影像處理、API 呼叫、決策邏輯 — 這些需要完整作業系統和較高算力
- **Arduino 負責「動作」**：步進馬達控制、伺服馬達定位、感測器讀取 — 這些需要精確的即時控制

兩者透過 Serial（UART）通訊，Pi 告訴 Arduino「放到第 3 槽」，Arduino 就驅動馬達執行。這種分工讓系統既有 Linux 的靈活性，又有微控制器的即時性。

### 機械設計的挑戰

卡片分類機最難的部分其實不是軟體，而是機械：

- **進紙**：如何可靠地一次只取一張卡片？（卡片會黏在一起、厚度不一）
- **定位**：卡片在攝影機前要夠穩定，才能拍到清晰的影像
- **分類投放**：如何快速切換到正確的分類槽？

這些問題在工業自動化中都有成熟解法，但要用 3D 列印零件和 Arduino 在桌上實現，需要大量的迭代調整。作者說這是「持續進化中」的原型，正是因為機械部分需要不斷微調。

### 為什麼用 Pi 3B+？

你可能會問：為什麼不用 Pi 5 或 Pi 4？

其實 Pi 3B+ 對這個應用完全夠用。卡片辨識不需要即時影像串流，而是「拍一張 → 處理 → 下一張」的批次模式。每張卡片的處理時間不是瓶頸，機械進紙和分類的速度才是。用 Pi 3B+ 還有個好處：便宜、省電、社群資源豐富。

## 心得與延伸

### 成本估算

| 項目 | 估計價格（USD） |
|------|-----------------|
| Raspberry Pi 3B+ | ~$35 |
| Arduino Nano | ~$5-20 |
| USB 攝影機或 Pi Camera | ~$10-25 |
| 步進馬達 + 驅動板 | ~$15-30 |
| 3D 列印零件 | ~$10-20（材料費）|
| **合計** | **~$75-130** |

不到 150 美元就能做出一台自動卡片分類機，比手動整理幾千張卡片省下的時間絕對值得。

### 延伸可能

- **多遊戲支援**：除了 MTG，同樣的架構可以辨識 Pokémon TCG、遊戲王等卡片，只要換辨識 API
- **價格追蹤**：辨識後自動查詢市場價格，產生收藏清單和總價值報告
- **稀有卡片警報**：偵測到高價卡片時發出提醒（「你知道這張值 $200 嗎？」）
- **更多分類槽**：目前原型的分類槽數量有限，可以用旋轉平台或輸送帶增加
- **速度優化**：升級到 Pi 4/5 + 更好的攝影機，搭配本地端 ML 模型，可能達到每秒 1-2 張的處理速度

### 學習價值

這個專案涵蓋了嵌入式系統開發的多個面向：

1. **雙控制器通訊**：Pi ↔ Arduino Serial 協定設計
2. **影像處理**：OpenCV 基礎、OCR 或影像比對
3. **API 整合**：Scryfall 等外部服務的呼叫與解析
4. **機械設計**：進紙、定位、分類的機構設計與 3D 列印
5. **系統整合**：軟硬體協同工作的除錯與優化

如果你有一大箱 TCG 卡片等著整理，這可能是你最好的入門專案動機。
